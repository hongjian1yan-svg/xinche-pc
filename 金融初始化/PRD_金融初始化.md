> 所属系统：智慧车市

## 一、背景与目标

### 1.1 背景

平台金融系统在使用前需要完成两项基础配置：金融公司信息录入、资金渠道配置。现有系统中：

- 金融公司管理已作为独立菜单存在，支持基本的增删改查
- 资金渠道配置依赖后端工程师直接操作数据库添加渠道名称，效率低、维护成本高
- 两个配置项分散在不同入口，没有体现"先配置公司、再配置渠道"的业务依赖关系

### 1.2 目标

1. 将金融公司管理与资金渠道管理合并为「金融初始化」统一入口
2. 在前端提供完整的资金渠道配置能力，消除对后端数据库操作的依赖
3. 建立"金融公司 → 资金渠道"的归属关系，使业务层级清晰可维护
4. 页面上下分区布局，引导用户先配置金融公司，再配置资金渠道

### 1.3 不在本次范围内

- 临时出场默认限制：该配置项属于市场级全局设置，保留在市场配置页面，不纳入本次需求
- 旧版资金渠道数据迁移：现有三个开通金融业务的市场，由运营人员在新功能上线后手动完成重新配置；配置完毕并确认业务正常后，由研发从市场配置页面移除旧的资金渠道配置模块
- 金融订单编号前缀：属于市场配置页面的关联改动，详见第八章

## 二、信息架构


```
市场（A市场）
└── 金融公司（如：泸州银行）

        ├── 放款比例
        ├── 车辆评估选项
        └── 评估平台（自动评估时必填）
```

## 三、页面整体结构

页面采用上下分区布局，两个模块在同一页面内顺序排列：

```
┌──────────────────────────────────────────────┐
│  【金融公司】模块标题                            │
│  筛选区                                        │
│  + 新增金融公司                                 │
│  金融公司数据表格 + 分页                         │
├──────────────────────────────────────────────┤
│  【资金渠道】模块标题                            │
│  筛选区                                        │
│  + 新增渠道                                    │
│  资金渠道数据表格 + 分页                         │
└──────────────────────────────────────────────┘
```

两个模块之间使用分割线或间距区分，各自拥有独立的筛选区、操作按钮和数据表格。

## 六、交互规则与异常处理

### 6.1 表单校验时机

- 每个字段失焦（onBlur）时触发单字段校验
- 点击确定/保存时触发全字段校验
- 唯一性校验在提交时由后端返回

### 6.2 删除确认弹窗（通用）

点击删除时，弹出二次确认：

| 属性 | 值 |
|------|---|
| 宽度 | `width="420px"`，`align-center` |
| 图标 | `WarningFilled`，#E6A23C，40px |
| 内容 | 确认删除？+ 名称信息卡片 + "删除后不可恢复" |
| 按钮 | 取消（默认）/ 确认删除（`type="danger"`） |

### 6.3 评估平台接口异常

多选框显示禁用状态，提示：

> "评估平台数据加载失败，请刷新页面重试"

### 6.4 网络/接口异常

所有操作接口异常时，统一通过 Message 组件在页面顶部提示错误信息。

## 八、关联改动：市场配置页面

### 8.1 金融订单编号前缀

**背景：** 金融订单编号由"前缀 + 日期 + 当日序号"组成，例如 `JHJR20260610001`。前缀标识订单所属市场，编号规则维持市场级别，不跟随金融公司或资金渠道变化。现有系统中该前缀由后端工程师手动维护，本次需提供前端配置入口。

**改动位置：** 市场配置页面 → 金融系统设置模块，新增"金融订单编号前缀"配置项。

| 属性 | 说明 |
|------|------|
| 字段名称 | 金融订单编号前缀 |
| 组件类型 | 单行文本输入框 |
| 必填条件 | 开启金融系统时必填 |
| 格式要求 | 2～6位大写字母（A-Z） |
| 唯一性 | 平台内所有市场不可重复 |
| 修改限制 | 产生第一笔金融订单后字段变为只读，tooltip 提示"已有金融订单，编号前缀不可修改" |
| 权限 | 仅超级管理员可编辑 |

### 8.2 开通金融系统引导顺序

1. 超管在市场配置中开启金融系统开关
2. 填写"金融订单编号前缀"（必填）
3. 保存市场配置
4. 前往「金融初始化」页面创建金融公司
5. 在资金渠道模块创建资金渠道
6. 金融系统正式可用

## 九、旧版数据处理说明

### 9.1 当前现状

市场配置页面金融系统设置中，现有"资金渠道"配置模块（含渠道名称、放款比例、评估方式）。目前共三个市场开通金融业务，存在部分旧渠道数据。

### 9.2 迁移方式

采用**人工重新配置**方式，不做自动化数据迁移：

1. 新功能上线后，由运营/管理员在「金融初始化」页面为三个市场逐一配置金融公司和渠道数据
2. 配置完成并确认金融业务运行正常后
3. 由研发将市场配置页面中的旧"资金渠道"配置模块移除

### 9.3 临时出场默认限制

该字段不纳入本次迁移，继续保留在市场配置页面，作为市场级全局设置维护。

## 十一、关联说明：APP 用款申请业务规则

本章说明资金渠道配置对 APP 端"用款申请"功能的影响规则，供 APP 侧研发参考。

### 11.1 多渠道场景下的用款比例计算

**背景：** 市场管理员可在 PC 端为同一市场配置多个资金渠道，每个渠道各有独立的放款比例。

**规则：** 当同一市场下存在多个资金渠道时，APP 用款申请功能计算可用款额度时，**以所有渠道中放款比例最高的值为准**进行计算。

**示例：**
- 渠道A：放款比例 80%
- 渠道B：放款比例 70%
- 渠道C：放款比例 90%

→ APP 用款申请中，系统按 **90%** 计算最大可用款额度。

---

### 11.2 车辆无法自动估值时的用款申请处理

**背景：** 部分质押车辆因车况特殊、数据缺失等原因，可能无法通过评估平台完成自动估值。不同市场对"未估价车辆能否质押"的管理策略存在差异，因此在市场配置中提供开关控制。

**市场配置开关：未估价车辆可申请用款**

| 属性 | 说明 |
|------|------|
| 配置位置 | 市场配置页 → 金融系统设置 → 评估平台字段之后 |
| 必填 | 是（标题前显示红色星号） |
| 组件类型 | 分段按钮（开启 / 关闭） |
| 默认值 | 关闭 |
| 提示文字 | 关闭后，无法获取估值的车辆将无法发起用款申请 |

**规则（开关开启时）：**

1. 车辆无法自动估值时，商户仍可在用款申请中**选择该车辆**，系统不予拦截
2. 由于车辆无法估值，系统**不自动计算最大用款额度**，用款额度输入框不预填值
3. 商户**自行输入用款金额**，填写完成后正常提交用款申请即可
4. 后续审核流程与正常估值车辆保持一致，由人工审核判断额度合理性

**规则（开关关闭时）：**

1. 车辆无法自动估值时，商户在用款申请中选择该车辆后，系统**拦截并提示无法申请用款**
2. 商户须在获得有效估值后方可继续提交用款申请
